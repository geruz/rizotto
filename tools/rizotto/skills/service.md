# Services

A service owns a piece of business logic and exposes it as RPCs. It is made of two
packages:

    services/order/order-client/   the contract: request/response types + the RPC interface
    services/order/                the implementation (package ordersrv)
    services/order/repository/     database access, only when the service owns a table

Callers never import the implementation — they import the client package and call
the bound RPCs. `rizotto service add` scaffolds all of it.

## 1. The contract

`services/order/order-client/client.go` holds the types and the interface. Every
method carries the address it is registered under:

```go
package order

type Order struct {
    ID   int    `json:"id"`
    Name string `json:"name"`
}

type GetOrderRequest struct{ OrderID int }

//go:generate genbind -client OrderClient
type OrderClient interface {
    // bind-method: http://order-service/order/get
    GetOrderRPC(ctx context.Context, req GetOrderRequest) (Order, bb.ServiceError)

    // bind-method: http://order-service/order/select
    SelectOrdersRPC(ctx context.Context, req SelectOrdersRequest) (OrderList, bb.ServiceError)
}
```

Rules the generator relies on:

- every method takes `(ctx context.Context, req <Request>)` and returns
  `(<Response>, bb.ServiceError)`;
- every method has a `// bind-method: <uri>` comment (use `// bind-event: <uri>`
  for fire-and-forget handlers);
- the interface is named `<Entity>Client`.

## 2. The generated bindings

`task gen` runs `genbind`, which writes `bind-gen.go` next to `client.go`:

- `RegisterServer(srv OrderClient)` — registers every method under its address;
- one function type per method (`GetOrderRPC`), which is what controllers store;
- `BindClient() OrderClient` — returns a client whose methods resolve the addresses.

Never edit `bind-gen.go`; change `client.go` and run `task gen`.

Registration and binding go through `bb`. `bb.MustRegister` puts the handler in the
process-wide table, `bb.MustBind` looks it up at call time, so a call is a direct
function call and an unregistered address answers with a not-implemented error.
`bb.StartHTTPEndpoint(ctx, port)` additionally serves the registered RPCs over HTTP.

## 3. The implementation

```go
package ordersrv

type OrderService struct {
    repo repository.OrderRepository
}

func NewOrderService(pool *pgxpool.Pool) OrderService {
    return OrderService{repo: repository.NewOrderRepository(pool)}
}

func (srv OrderService) GetOrderRPC(
    ctx context.Context, req order.GetOrderRequest,
) (order.Order, bb.ServiceError) {
    id, svcErr := toOrderID(req.OrderID) // input validation belongs to the service
    if svcErr != nil {
        return order.Order{}, svcErr
    }

    found, err := srv.repo.GetOrderByID(ctx, id)
    if err != nil {
        if pg.IsNotFoundError(err) {
            return order.Order{}, bb.NewNotFoundError("order not found")
        }

        return order.Order{}, bb.NewInternalError("failed to get order", err)
    }

    return toOrder(found), nil
}
```

A service without a database keeps its state in memory instead (a slice guarded by
a `sync.RWMutex`) and its constructor takes no arguments.

### Errors

Return `bb` errors, never raw ones: they carry the status the error deserves, the
controller turns them into HTTP errors with `gateway.MapError`, and the bb HTTP
transport renders them with the same status.

    bb.NewNotFoundError("order not found")            404
    bb.NewInvalidRequestError("invalid order id")     400
    bb.NewValidationError(code, "message")            400 with a public error code
    bb.NewUnauthorizedError("no access")              401
    bb.NewInternalError("failed to …", err)           500, the cause stays in the logs

`bb.IsNotFoundError(err)` and `bb.IsValidationErrorWithCode(err, code)` inspect an
error coming back from another service.

## 4. Registering the service

In `server.go`:

```go
import (
    ordersrv "<module>/services/order"
    "<module>/services/order/order-client"
)

order.RegisterServer(ordersrv.NewOrderService(pgPool)) // NewOrderService() without a database
```

Register every service before `ListenAndServe`; a controller bound to an
unregistered address fails at request time, not at start-up.

## 5. The repository and the database

```
services/order/repository/order-repository.go  the only place that talks to the database
services/order/repository/sql/schema.sql       the schema sqlc type-checks against
services/order/repository/sql/order-queries.sql the queries
services/order/repository/db/                  generated by sqlc — do not edit
services/order/repository/migrations/          dbmate migrations
```

The repository embeds `pg.Repository` and holds the generated `*db.Queries`:

```go
func NewOrderRepository(pool *pgxpool.Pool) OrderRepository {
    return OrderRepository{Repository: pg.NewRepository(pool), queries: db.New(pool)}
}

func (r OrderRepository) GetOrderByID(ctx context.Context, id int32) (db.Order, error) {
    return r.queries.GetOrder(ctx, id)
}
```

Queries are annotated for sqlc and regenerated with `task gen` (it runs sqlc in
docker, driven by `sqlc.yaml`, which has one entry per service):

```sql
-- name: GetOrder :one
SELECT * FROM public.orders WHERE id = $1;

-- name: SelectOrders :many
SELECT * FROM public.orders ORDER BY created_at DESC, id DESC LIMIT $1 OFFSET $2;
```

Every schema change needs both a migration (`repository/migrations/`, applied by
`task migrate-up`) and the matching edit in `repository/sql/schema.sql`, which is
what sqlc reads. `pg.IsNotFoundError(err)` recognises "no rows"; use `WithTx` on the
queries for transactions.

## 6. Testing

Register the service and call it through its own client — that exercises the
bindings as well:

```go
order.RegisterServer(ordersrv.NewOrderService())
client := order.BindClient()

created, err := client.CreateOrderRPC(ctx, order.CreateOrderRequest{Name: "table"})
```

Controllers are tested against mocked RPCs instead, see `rizotto controller skill`.

## Adding one

    rizotto service add          # asks for the name, the database and the CRUD methods

It writes the contract, the bindings, the implementation and, when the service owns
a table, the repository, the schema, the queries, the generated db package and the
first migration, and registers the queries in `sqlc.yaml`.
